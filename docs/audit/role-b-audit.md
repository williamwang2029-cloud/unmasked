## 5. Methods

- **Planting (reid/plant.py).** Deterministically inserts synthetic names, `@bu.edu` emails,
  `U########` IDs, and phone numbers into ~30% of comments (plus ~10% decoys, ~60% clean),
  emitting character-span ground truth. Params: `seed=42`, `pct_pii=0.30`, `pct_decoy=0.10`
  (from the reference, for reproducibility).

- **k-anonymity + greedy generalization (reid/mitigate.py).** An equivalence class = rows
  sharing all quasi-identifier (QI) values; k-anonymity means every class has >= k rows. The
  greedy optimizer starts all QIs at level 0 and repeatedly raises the column with the best
  gain/cost (drop costs 2, coarsen costs 1) until below-k share <= `max_suppression`; the
  remainder is suppressed. Params: `k=5`, `max_suppression=0.05`,
  `max_group_suppression=0.10` (protect-on), `group_col=affiliation`. Two modes: protect-on
  keeps the small-group column and caps per-group suppression; protect-off does not.

- **HMAC tokenization + Fernet vault (reid/tokens.py).** Join keys are HMAC-SHA256 (first 16
  hex chars) over the value, deterministic so equal inputs map to equal tokens (joinable).
  Original values are Fernet-encrypted into a per-column vault (`keys/vault_<col>.csv`); the
  vault key lives in `keys/vault.key`. `detokenize` reverses via the vault or raises KeyError.
  Keys are separated from data and never committed.

- **Presidio NER + custom recognizer (reid/pii_text.py).** Presidio with the small spaCy model
  `en_core_web_sm` plus a custom BU_ID regex recognizer (`\bU\d{8}\b`, score 0.9). Returns only
  PERSON, EMAIL_ADDRESS, PHONE_NUMBER, BU_ID. Default `threshold=0.35`. Post-filters: PERSON
  deny-list (exact common words) and place-word rule (building/location names). Scoring: a
  prediction is a true positive iff it shares entity type and overlaps an unmatched truth span;
  each truth matched once.

- **ML utility test (reid/utility.py).** `HistGradientBoostingRegressor` predicts the `SE`
  scale from the other columns (excluding `SE*`, ids, metadata, planted), trained on original
  vs released data and tested on the same held-out original rows (release model sees them via
  the generalization transform) so R2 is directly comparable. `seed=42`, 80/20 split.

- **Linkage attack (Role A's attacks.py, consumed by the runner).** Models an adversary who
  knows some QIs (personas) and joins them to the release; reports the correctly re-identified
  rate before vs after mitigation.

## 8. AI and LLM usage

**LLM in Role B code:** only `reid/pii_text.py` `llm_detect`, via `reid/llm.py` (Role C).
It sends only the **synthetic planted comment text** (a short survey comment) and asks for a
JSON list of PII spans. It never sends survey rows, scales, or identifiers — the detection path
operates on free-text comments only, which are synthetic. Fallback: `llm_detect` returns `[]`
when the LLM is disabled or returns a non-list, so detection still runs with Presidio alone. In
the committed `results/detection.csv` the LLM was disabled, so only Presidio rows are present
(no `llm`/`combined` rows) — i.e. the fallback path is what produced the shipped numbers.
Provider/model config is environment-driven in `reid/llm.py` (LLM_PROVIDER / LLM_MODEL); no keys
are in the repo (`.env` is gitignored). Exception to "metadata only": the synthetic comments are
row-derived text, but they are fabricated test data, not real student responses.

## 10. Known issues and limitations

- **PERSON recall ~0.91 (Medium).** The small spaCy model misses some names, especially the
  second name in a sentence ("my roommate X and Y"); confirmed out-of-sample. A larger model
  would help but was out of scope.
- **Place-word rule is heuristic (Low).** Keyed on a fixed 7-word list; "Agganis Arena" slips
  through because "Arena" isn't listed. Deliberately not expanded, to avoid overfitting.
- **Optional tests not implemented (Medium).** Property tests for plant span integrity, token
  round-trip, monotone generalization, lockstep drop, suppression completeness, and detection
  scoring (tasks 1.2/1.3/2.3/2.4/2.5/3.2/4.3/5.2) were skipped for the MVP; correctness rests on
  acceptance checks, not property-based tests.
- **run_experiments.py tasks unchecked (Low).** Tasks 6.1/6.2/7 are functionally done but not
  marked complete in tasks.md.
- **Environment requirements (Medium).** Python 3.11.9; pandas 3.1.0, scikit-learn 1.9.1,
  spacy 3.8.16 + `en_core_web_sm`, presidio-analyzer, cryptography, faker, pyyaml. Checks were
  run from the repo's `.venv`; runtimes ~5-9s depend on load path (clean parquet vs xlsx).
- **Backups left on disk (Low).** `data/*_mine.parquet` remain locally at user request;
  gitignored, so no repo impact.
- **LLM detection path unexercised in shipped results (Low).** Only Presidio rows exist in
  `detection.csv`; `llm`/`combined` methods are untested against a live model here.

## 12. Presentation material

**Talking points:**
1. "Metadata is the leak": survey date + duration alone make ~99.99% of students unique.
2. One optimizer, two postures: a "fair" mode keeps demographic grouping and caps the worst
   group's suppression (2.5% removed); a "max-utility" mode drops it (3.5% removed).
3. The attack story: 68.5% of targets re-identified on raw data, 0% after mitigation.
4. Utility survives: an ML model predicting student engagement keeps R2 0.42 -> 0.37.
5. Free-text safety net: Presidio + custom rules scrub emails/phones/IDs at 100%, names at 91%.

**Best charts (on `main` from Role A's notebook, `results/charts/`):**
`attack_before_after.png` (re-identification before vs after), `fairness.png` (per-group

are added). NOTE: these PNGs are not on the `role-b` branch; they live on `main`.

**Key insight (one sentence):** You can cut re-identification risk from near-certain to zero
while suppressing only a few percent of records — and you get to choose who pays the cost.
